# WireframeNode: 설명 카드 → 실물 컴포넌트 목업 렌더링

## 배경 및 목표

PRDView는 마크다운 PRD를 파싱해 `WireframeNodeData` 트리(`name`, `props`, `events`, `children`)로 만들고, 이를 `WireframeNode.tsx`가 카드 형태로 렌더링한다. 현재 렌더링은 "이 노드는 Button입니다"라는 사실을 아이콘 하나 + 모노스페이스 이름 라벨 + Props/Event 텍스트 나열로 설명하는 **스펙 카드**에 가깝다. 모든 타입(버튼/인풋/카드/모달/…)이 흰 배경 + 회색 2px 테두리로 동일하게 그려져서, 실제로 화면이 어떻게 생겼는지 한눈에 들어오지 않는다는 피드백이 있었다.

이 작업의 목표는 `WireframeNode`가 컴포넌트 종류를 "설명"하는 대신, 그 컴포넌트처럼 **보이는 목업**을 그리도록 바꾸는 것이다. 그레이스케일 로파이 와이어프레임(Balsamiq류) 톤을 기본으로 하되, 변경 사항(diff)만은 색으로 확실히 튀게 한다.

## 범위

- **변경**: `src/components/WireframeNode.tsx`와 그 안의 `getComponentUiInfo` 타입 추론 로직.
- **변경 안 함**: `src/components/ScreenCard.tsx`(루트 화면 프레임, 섹션 헤더), `TocSidebar`, `TopHeader`, 전체 페이지 톤(`bg-dot-grid` 등). 화면을 감싸는 틀은 지금 스타일을 그대로 유지한다.
- 데이터 모델(`WireframeNodeData` in `src/types.ts`)은 변경하지 않는다 — 위치/레이아웃 힌트가 없으므로 컴포넌트 배치는 계속 세로 스택 기준이다(단, container 타입 내부에서는 아래 설명대로 예외가 있다).

## 타입 분류: Leaf vs Container

기존 `getComponentUiInfo`가 이름 문자열에서 추론하는 카테고리를 두 그룹으로 나눈다.

| 그룹 | 타입 | 자식 처리 |
| --- | --- | --- |
| Leaf | Button, Input Field, Media/Avatar | 자체로 완결된 박스. `children`이 존재해도(드문 경우) 지금처럼 아래에 들여쓰기로 처리 |
| Container | Header/Nav, Card Component, Modal/Popup, Table Data, List View, UI Component(fallback) | 자식 노드를 박스 **안쪽에** 중첩 렌더링 |

## 타입별 시각 표현

모든 타입은 그레이스케일 톤(흰 배경 또는 옅은 회색 채움, 회색 테두리)을 기본으로 하고, 타입별 accent color는 이제 아이콘 한 곳에만 남긴다(박스 전체에는 쓰지 않음 — "색상 방침" 참고).

- **Button** (leaf): 회색 채움 박스, 둥근 모서리. `node.name`이 버튼 안의 텍스트로 그대로 들어간다.
- **Input Field** (leaf): 흰 박스 + 테두리. `node.name`이 플레이스홀더 텍스트로 들어간다(옅은 회색).
- **Media/Avatar** (leaf): 회색 박스 + 이미지/아바타 아이콘 중앙 배치. `node.name`은 박스 아래 작은 캡션으로 표시(아이콘 자리엔 텍스트를 넣을 자연스러운 위치가 없으므로).
- **Header/Nav** (container): 가로로 넓은 바. `node.name`을 좌측 브랜드/타이틀 텍스트로 쓰고, 자식들은 세로 들여쓰기 대신 **가로로 나열된 메뉴 아이템**으로 렌더링한다.
- **Card Component** (container): 테두리 있는 박스. `node.name`을 박스 상단의 작은 제목으로 쓰고, 자식은 안쪽 패딩 영역에 중첩 렌더링한다.
- **Table Data** (container): 자식이 있으면 각 자식의 `node.name`을 헤더 행의 컬럼 제목으로 삼아 단일 헤더 행 + 빈 데이터 행 1줄짜리 그리드 스켈레톤을 그린다. 자식이 없으면 컬럼 2개짜리 플레이스홀더 그리드로 대체한다.
- **List View** (container): 자식이 있으면 각 자식을 리스트 행 하나로(자식의 `node.name`을 행 텍스트로) 반복 렌더링한다. 자식이 없으면 회색 스켈레톤 바 2~3줄로 대체한다. `node.name`은 목록 제목.
- **UI Component / Box** (fallback, container): Card Component와 같은 구조지만 타입 색이 없는 중립 회색 박스로 그린다(추론 실패 시의 안전한 기본값).

기존에 있던 접기/펼치기(chevron) 컨트롤은 container 타입에서 그대로 유지한다(자식이 많아지면 여전히 필요).

## 색상 방침

그레이스케일 로파이 스타일을 선택했으므로, 타입별 색(버튼=파랑, 인풋=초록 등)은 박스 전체 배경/테두리에는 쓰지 않고 지금처럼 헤더의 작은 아이콘 색상에만 남긴다. 색은 diff 신호를 위해 아껴둔다 — 그래야 "뭔가 바뀐 컴포넌트"가 무채색 캔버스 위에서 확실히 튄다.

## Diff 표시

변경된(added/modified) 노드는 초록색 은은한 글로우 링(`box-shadow`, 기존 `ring-4 ring-[#10B981]/15`와 동일 계열)으로만 표시한다. NEW/MODIFIED를 구분하던 텍스트 뱃지(현재의 solid/outline 초록 pill)는 제거한다 — 이 구분은 상단 diff 알림 배너와 브리핑 모달이 이미 담당하고 있으므로 컴포넌트 레벨에서 중복으로 보여줄 필요가 없다는 판단.

## Props / Events 표시

컴포넌트 박스 아래에 한 줄, 작고 흐린 회색 텍스트로 상시 노출한다. 예: `props: id, disabled · onClick`. 지금처럼 별도 박스/테두리를 두르지 않고, 값이 없는 항목(props 없음, events 없음)은 그 부분을 생략한다.

## 라벨 처리

코드 스타일의 이름 뱃지(`font-mono` 박스 안에 아이콘+이름)는 없어진다. `node.name`은 각 컴포넌트 타입에 맞는 실제 화면 텍스트 위치(버튼 라벨, 인풋 플레이스홀더, 모달/카드 제목 등)에 그대로 사용한다. 이름 길이에 따른 별도 처리(말줄임, 캡션 분리)는 하지 않는다 — 길면 긴 대로 표시하되 컨테이너 폭 안에서 자연스럽게 줄바꿈/말줄임 처리한다.

## 명시적으로 다루지 않는 것

- 컴포넌트의 2차원 배치(가로 그리드 등)는 다루지 않는다 — 데이터 모델에 레이아웃 힌트가 없으므로 세로 스택 기준을 유지한다(Container 내부의 가로 나열은 타입 고유의 표현일 뿐, 범용 레이아웃 시스템이 아니다).
- `ScreenCard.tsx`의 루트 화면 프레임 스타일은 변경하지 않는다.
- 이름 기반 타입 추론 로직 자체의 정확도 개선(정규식 확장 등)은 이번 스코프에 포함하지 않는다.
